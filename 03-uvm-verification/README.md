# UVM Verification of the Canny Edge Detection IP Core

This directory contains the third development stage of the license plate detection system: SystemVerilog/UVM verification of the VHDL Canny Edge Detection accelerator.

The verification environment exercises the AXI4-Lite control interface and the AXI4-Full image-transfer interface, starts the accelerator, waits for processing to complete, reads the generated edge image, and compares the DUT output with SystemC-generated golden reference vectors.

## Verification Goals

The main verification goals are:

- verify AXI4-Lite register configuration;
- verify AXI4-Full burst image transfers;
- verify the start/ready synchronization mechanism;
- verify output-image readback;
- compare the VHDL DUT output with SystemC reference data;
- collect functional coverage;
- automate execution of multiple tests and coverage reporting.

## DUT

The Device Under Test is the VHDL Canny Edge Detection IP core developed in the previous project stage.

The DUT contains:

- an AXI4-Lite interface for control, configuration, and status;
- an AXI4-Full interface for input-image transfer and output readback;
- a BRAM-based memory subsystem;
- the FSM-based Canny Edge Detection accelerator.

## UVM Environment

The verification environment contains the following main components:

### Sequence Item

The transaction class represents the operations used during verification, including:

- AXI4-Lite register writes;
- AXI4-Lite register reads;
- AXI4-Full write bursts;
- accelerator start;
- waiting for the ready status;
- output-result readback.

### Sequencer

The sequencer receives sequence items from the active sequences and forwards them to the driver.

### Driver

The driver converts UVM sequence items into signal-level AXI4-Lite and AXI4-Full transactions on the DUT interface.

Its responsibilities include:

- register configuration;
- burst-based image transfer;
- start-signal generation;
- ready-status polling;
- output-memory reads.

### Monitor

The monitor observes DUT-interface activity and forwards collected transactions to the scoreboard and coverage components.

### Scoreboard

The scoreboard compares the edge image produced by the VHDL DUT with SystemC-generated golden reference vectors.

The comparison is performed pixel by pixel within the valid image-processing region.

### Functional Coverage

The coverage component records whether relevant transaction types, configuration values, control operations, and processing scenarios have been exercised.

### Agent and Environment

The UVM agent groups the sequencer, driver, and monitor.

The environment connects the agent with the scoreboard and functional coverage components.

## Verification Flow

A typical verification sequence performs the following steps:

1. Configures image dimensions and Canny threshold values through AXI4-Lite.
2. Transfers the grayscale input image through AXI4-Full bursts.
3. Activates the accelerator through the start register.
4. Waits for the ready status to indicate processing completion.
5. Reads the final edge image from the output memory region.
6. Sends the observed result to the scoreboard.
7. Compares the DUT output with the SystemC reference data.
8. Collects functional coverage and reports errors.

## Test Data

The `golden_vectors` directory contains input data and reference results generated by the SystemC model.

The environment supports verification with both real input images and synthetic test patterns.

## Regression and Coverage

The Tcl regression script automates:

- execution of multiple UVM tests;
- selection of tests through `UVM_TESTNAME`;
- collection of simulation logs;
- storage of individual coverage databases;
- generation of individual coverage reports;
- generation of a merged coverage report.

Vivado XSim is used as the simulation engine.
